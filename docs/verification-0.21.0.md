# 0.21.0 の検証結果と残っている問題

2026-09-30 時点。対象は main の a9067d6（npm 0.21.0、タグ `v0.21.0`）である。

0.21.0 は完全ではない。0.21.0 で入った重大な後退が1件あり、再現を確かめた。0.20.0 からあった不具合2件、自己参照の外部キーで子行が消えることと STRICT 表の `ANY` 列の値の型が変わることは直した。
この文書は 0.21.1 で直すものの一覧で、直したら該当する行を消す。すべて直したらこの文書を消す。

## 検証の方法

6つの観点で、互いに独立に検証した。

| 観点             | 内容                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| コードの正しさ   | 5a6e46e と 47f77a0 の変更を、欠陥を探す立場で読み、疑わしい点は小さなスクリプトで再現した          |
| 互換性と移行     | 0.20.0 との混在、0.20.0 の DB の移行、復元と写しの取り合いの検出、初参加の端末、表名の大文字小文字 |
| スキーマの一般性 | 特殊な表名・列名、仮想表、WITHOUT ROWID、AUTOINCREMENT、列の追加と削除、制約、STRICT               |
| 性能と資源       | 写しの大きさと作る時間、転送回数、スレッドが止まる時間、一時ファイルの残骸                         |
| 文書             | 設計書・README・CHANGELOG・ソースのコメントと実装の一致、原則との関係                              |
| 試験一式         | 全体の試験、網羅検査3本、人工バグ6つで試験が気づくか                                               |

## 修正が必要な問題

| 重大度 | 問題                                                                                                                            | 原因                                                                                               | 由来          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------- |
| 重大   | UTF-16 の DB では、同期が毎回 `attached databases must use the same text encoding as main database` で止まり、行が1つも届かない | `src/nas.ts` の `writePublishedTables` が写しの DB を UTF-8 で作り、そこへ元の DB を `ATTACH` する | 0.21.0 の後退 |

1台だけで再現する。再現手順は末尾にある。

混在中の時刻の問題は、コードでは直さないと決めた。
0.20.0 の端末が時刻列に ISO-8601 でない値を書くと、その値が 0.21.0 の端末に届き、届いた端末は次の `setupSync` で例外になる。
時刻列の値の意味はアプリにしか分からないので、アプリのマイグレーションで扱う。
CHANGELOG 0.21.0 の移行の説明は、この前提で訂正した。訂正はまだコミットしていない。

## 0.21.0 の変更による資源の悪化

NAS の写しを小さくした代わりに、手元の一時領域とスレッドが止まる時間が悪くなった。
測ったのは M1 Pro の SSD 上で、実際の NAS ではない。

| 項目                       | 0.21.0                                        | 変更前                                   | 影響                                                            |
| -------------------------- | --------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------- |
| 手元の一時領域             | DB の約1.5倍。500 MB の DB で 898 MB          | 使わない                                 | 空きが足りないと `SQLITE_FULL` で毎回失敗し、写しを上げられない |
| スレッドが続けて止まる最長 | 100 MB の DB で約 0.25 秒、500 MB で約 1.1 秒 | 23〜48 ms。`backup()` は細かく分けて進む | Electron の主プロセスでは画面が固まる                           |
| 表の多い DB での写しの作成 | 200表で 332 ms。`ATTACH` だけで毎回約 190 ms  | 63 ms                                    | トリガーの SQL（22.8 MB）を `ATTACH` のたびに読み込む           |

写しの作り方は、「他の端末が読む表だけを載せる」方式を保って改良するか、0.20.0 と同じ DB 全体の写しに戻すかを決める必要がある。

## 検証していない範囲

上の問題をすべて直しても、他に問題が無いとは言えない。言えるのは、試した範囲では上のもの以外は見つからなかったということまでである。

- 網羅検査は深さ2まで。深さ3 は 0.21.0 の変更の後では完走していない
- 環境は手元の macOS の SSD だけ。実際の NAS（SMB・NFS）、Windows、Electron の主プロセスでは動かしていない
- 試したのは合成の DB とスキーマで、実際のアプリの DB では測っていない
- アプリ独自の照合順序は試せなかった。better-sqlite3 に登録する API が無い

自己参照の外部キーの問題は、既存の試験も網羅検査も捕まえていなかった。まだ試していない種類のスキーマや操作に、同じように問題が残っている可能性がある。

## 修正の順序の提案

0.21.1 として、公開済みの版で入った後退とデータを失う不具合から直す。

1. UTF-16 の後退を直す。写しの DB の文字コードを元に合わせる
2. 写しの作り方を見直し、一時領域とスレッドが止まる時間の悪化を抑える
3. 軽微な問題と文書を直し、試験を足す。対象は上で見つかった壊れ方と、人工バグで気づかなかった3つ

## 再現手順

`npm run build` のあとにリポジトリの直下で動く。`TMPDIR` には空のディレクトリを渡す。

```js
// repro.js — 使い方: TMPDIR=<空のディレクトリ> node repro.js
const path = require('path')
const Database = require('better-sqlite3')
const { setupSync } = require('./dist/index.js')

const T = '2026-01-01T00:00:00.000Z'

;(async () => {
  const dir = process.env.TMPDIR
  const dbPath = path.join(dir, 'a.sqlite')
  const db = new Database(dbPath)
  db.pragma(`encoding = 'UTF-16le'`)
  db.exec(
    `CREATE TABLE notes (id TEXT PRIMARY KEY NOT NULL, body TEXT, updatedAt TEXT NOT NULL)`
  )
  db.close()
  const sync = setupSync({
    dbPath,
    nasPath: path.join(dir, 'nas'),
    clientId: 'a',
    schemaVersion: '1',
  })
  const app = new Database(dbPath)
  app.prepare(`INSERT INTO notes VALUES ('x', 'hello', ?)`).run(T)
  const show = () => app.prepare(`SELECT * FROM notes`).all()
  console.log('before', show())
  try {
    await sync.syncNow()
  } catch (error) {
    console.log('threw', error.message)
  }
  console.log('after ', show())
  sync.stop()
  app.close()
})()
```

正しい結果は例外が出ないこと。0.21.0 では `attached databases must use the same text encoding as main database` の例外になる。
