# 親の畳みが無効になっても、子の畳みは無効にならない

別 id・同一ユニークキーの2行を1行へ統合する（畳む）とき、その2行にぶら下がる子も
同じ理由で統合されることがある。あとから親の畳みが無効になっても、**その親を根拠に
行われた子の畳みは無効にならない。**

以下は、あるべき実装（下記の規則1〜4）を前提とした手順である。

## 規則

1. **畳みの記録（`_id_merge` / `_tombstone`）には、勝った行の `updatedAt` を書く。**
   同期時刻は書かない。畳み先が更に畳まれて記録を終端へ張り替えるときも、
   **この時刻は動かさない**（向き先が変わっただけで、畳まれた時刻は変わらない）
2. **読み替えは、その記録が子の参照より新しいときだけ適用する**
3. **読み替えて書き換えた行のうち、LWW に勝って実際に保存されるものだけが、記録の
   時刻を名乗る。** 書き換えた後の内容は勝った側の版に由来するので、その版の時刻を
   名乗る。負けた側の版の時刻は残さない。**保存されない行は名乗らない** ——
   比べる前の挑戦者に名乗らせると、古い版が新しい編集を上書きする
4. **畳みの記録は、敗者行がその記録より新しく更新されていれば無効**

ライブラリにはもう1つ規則がある（遅れて届いた子の親が消えているとき、スキーマの
`ON DELETE` に従って扱う）。この文書の範囲外なので `README.md` を参照。
以下で述べる「畳みの撤回」は、それとは別のものである。

## 前提

| テーブル | 内容 |
| --- | --- |
| `exam_students` | 「この試験にこの生徒が受験する」。`UNIQUE(examId, studentId)` |
| `score_decisions` | 採点の確定。親は `exam_students`。`UNIQUE(examStudentId, regionId)` |

主キーは uuid。2つの端末が同じ実体を独立に作ると、中身が同じで id だけ違う行が2つできる。
id は端末A が作ったものを `es-a` / `sd-a`、端末B が作ったものを `es-b` / `sd-b` と書く。
時刻は `0001`, `0002`, … の順とする。

### 子にユニーク制約が無い場合は、この現象は起きない

**子の畳みが起きるのは、子の側にもユニーク制約があるときだけである。** 無ければ2つの子は
衝突せず、両方が勝った親にぶら下がり、両端末が一致する（実測）。

この文書の利用側アプリ（score-at-once）で `exam_students` を親に持つ子のうち、ユニーク制約を
持つのは3つだけである（実スキーマで確認）。

```
StudentAnswerImage   UNIQUE(examPageId, examStudentId)        答案画像
ScoreDecision        UNIQUE(cropRegionId, examStudentId)      採点の確定
CompoundAnswerScore  UNIQUE(compoundAnswerId, examStudentId)  複合解答の採点
```

**`QuestionScore`（設問ごとの生の採点）にはユニーク制約が無い。** したがって以下の現象は
生の採点には起きず、上の3つに起きる。

## 手順

### 1. 先生A が山田を追加し、設問1を採点する

| | `exam_students` | `score_decisions` | 畳みの記録 |
| --- | --- | --- | --- |
| **A** | `es-a` 山田 **0001** | `sd-a` → `es-a` 設問1「A確定」**0002** | — |
| B | — | — | — |

### 2. A が同期する（push のみ）

### 3. 先生B が独立に山田を追加し、同じ設問1を採点する

| | `exam_students` | `score_decisions` | 畳みの記録 |
| --- | --- | --- | --- |
| A | `es-a` 山田 0001 | `sd-a` → `es-a` 0002 | — |
| **B** | `es-b` 山田 **0003** | `sd-b` → `es-b` 設問1「B確定」**0004** | — |

### 4. B が同期する

**(1) `es-a`（0001）を取り込む**

`(試験1, 山田)` は1行しか置けない。LWW で `es-b`（0003）が勝つ。

規則1 により、記録の時刻は勝った `es-b` の `updatedAt`。

```
es-a → es-b   0003
```

この記録が必要な理由: `es-a` は全端末で死ぬが、他の端末には `es-a` を親とする子が
まだ在る。その子がそのまま届くと、親が存在しないため外部キー違反になり、その相手から
取り込んだぶんが丸ごと巻き戻って、その端末からのデータが永久に届かなくなる。

**(2) 続けて `sd-a`（0002）を取り込む**

親の `es-a` で記録を引く。規則2 の判定:

```
記録 0003  >  sd-a の 0002   →  記録の方が新しい  →  読み替える
```

親を `es-b` に書き換える。

```
id=sd-a  親=es-b  設問1  "A確定"  updatedAt=0002
```

これが `(es-b, 設問1)` で `sd-b` と衝突する。LWW で `sd-b`（0004）が勝つ。

**この `sd-a` は保存されないので、規則3 の名乗りは起きない**（0002 のまま）。名乗るのは
保存された行だけである。ここでは勝敗の結果も変わらない（0002 でも 0003 でも `sd-b` の
0004 に負ける）。

```
es-a → es-b   0003
sd-a → sd-b   0004
```

| | `exam_students` | `score_decisions` | 畳みの記録 |
| --- | --- | --- | --- |
| A | `es-a` 山田 0001 | `sd-a` → `es-a` 0002 | — |
| **B** | `es-b` 山田 0003 | `sd-b` → `es-b` 0004 | `es-a→es-b 0003`、`sd-a→sd-b 0004` |

### 5. A が生徒を付け替える（0006）

| | `exam_students` | `score_decisions` |
| --- | --- | --- |
| **A** | `es-a` **佐藤** **0006** | `sd-a` → `es-a` 0002 |
| B | `es-b` 山田 0003 | `sd-b` → `es-b` 0004 |

### 6. 同期する

**親の記録は無効になる。** 規則4:

```
es-a の行 0006  >  記録 0003   →  記録は無効
```

`es-a`（佐藤）が復活し、読み替えも行われない。両端末に2人とも揃う。

**子の記録は有効なまま。** 規則4:

```
sd-a の行 0002  <  記録 0004   →  記録は有効
```

A の `sd-a`（0002）は削除される。

## 最終状態

| | `exam_students` | `score_decisions` |
| --- | --- | --- |
| A | `es-a` 佐藤、`es-b` 山田 | `sd-b` → `es-b`（山田）のみ |
| B | `es-a` 佐藤、`es-b` 山田 | `sd-b` → `es-b`（山田）のみ |

規則1〜4 では、佐藤の設問1の確定は失われたままである。

## B が確定していなかった場合

手順4(2) で衝突相手が居ないため、書き換えられた `sd-a` がそのまま入る。規則3 により
`updatedAt` は 0003 に進んでいる。

| | `score_decisions` |
| --- | --- |
| A | `sd-a` → `es-a` **0002** |
| B | `sd-a` → `es-b` **0003** |

同期すると 0003 > 0002 なので B の版が勝ち、両端末が `es-b` で一致する。

規則3 を入れる理由は収束ではない。**書き換えた後の `親=es-b` という内容は、勝った
`es-b` の版に由来する。** `sd-a` が持っていた「親は `es-a`」という主張は、`es-a` が
負けた時点で無効になっている。生き残った行が名乗るべきは勝った側の時刻であり、
負けた側の時刻でも、同期を回した時刻でもない。規則1 と同じ原則である。

収束はその帰結として得られる。規則3 が無ければ両方 0002 で同点になり、永久に
食い違ったままになる。同一主キーの LWW は「厳密に新しい」ものだけを採るため、同点は
両側で `skipped` になり、決着をつける規則が存在しない（別 id の畳みには主キー辞書順の
同点処理があるが、同一主キーの経路には無い）。

なお規則2 が「記録の方が新しいときだけ読み替える」ため、規則3 の書き換えは必ず前進で、
時刻が巻き戻ることはない。

## 規則1〜4 で足りないもの

手順4(2) の子の畳みは、`es-a` と `es-b` が同じ生徒だという前提で行われた。手順5 で
その前提は崩れている。

親の記録は規則4 で無効になるが、**子の記録は、その親を根拠に作られたことを知らない。**
したがって無効にならない。

> **親の畳みが無効になったら、その親を根拠に行われた子の畳みも無効にする。**

これには子の畳みの記録に「どの親の畳みが原因か」を持たせる必要がある。現在はどこにも
持っていない。

**規則1〜4 は収束を回復する。この「畳みの撤回」は失われた行を回復する。両者は別のものである。**
